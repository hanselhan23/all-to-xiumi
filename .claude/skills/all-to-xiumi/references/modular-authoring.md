# 秀米原生模块化操作与验证

在需要继续编辑或交接模板时使用本参考。以下组件字段和导出行为来自实际秀米草稿验证；不同版本应先读取当前编辑器自身的模板矩阵，不能只凭历史字段猜测。

## 原生组件与可编辑边界

从当前秀米的“布局/基础布局”及图片模板获取矩阵，保留完整 `_comp`、`tplId`、`constraint`、`pose`、`style`，为复制的组件生成唯一 `_$uuid`，递归清除 `$$` 开头的 Angular 运行时缓存。渲染入口仍是 `pages[0].layers[0].comps.items`；修改需经过作用域更新，不能以页面 `innerHTML` 的暂时显示代替持久组件。

已验证的结构示例：

- 单列原生布局：`paper-cp:layout/row1-r1c1`，`col1.type = "group"`，正文放在 `col1.items`。
- 双列原生布局：`paper-cp:layout/row1-r1c2`，左右分别放在 `col1.items`、`col2.items`。
- 原生文字：`paper-cp:header/1-txt-normal`，内容在 `txt1.text`。段落的字体和行距可以保留在行内样式中。
- 原生图片：`paper-cp:image/img-autowidth`，图片节点是 `img1`，具有 `type: "image"`、`src` 和 `style`。使用秀米图库上传得到的持久 CDN 地址。

外框和文字是不同组件。外框保留边框、阴影、装饰和内边距，宽度/外边距等放置属性按原布局映射，文字用自动高度。多列照片的边框、倾斜和说明归属于各列，图片另设原生组件。替换图片时检查原模板如何决定尺寸：自动宽度图片可能按固有比例输出，不能假设 `img1.style.height` 总会保留；需要固定图片槽时，在外层保留比例、高度和裁切范围，并测试不同宽高比的图片。

复杂背景或 SVG 动效可以留在独立装饰组件中，正文继续使用原生模块。不必为实现编辑把矢量动画栅格化。零高度装饰容器应检查每一层外包装的高度、溢出和行高，避免装饰占用正文高度或把后续文字裁掉。增加正文后，检查背景原有覆盖范围是否仍足够；不能承诺任意扩展篇幅仍保留全部背景。

## 样式迁移中已验证的细节

### 多层背景与角部装饰

原生渲染器主要读取 `backgroundImage`、`backgroundColor`、`backgroundPosition`、`backgroundSize`、`backgroundRepeat` 等长属性。浏览器解析多层 `background` 简写后，返回值可能包含逗号列表中的 `initial`；将这些值直接写回长属性会变为无效 CSS，表现为角部装饰消失。

分别用对应初值规范化：`backgroundImage` 用 `none`，`backgroundSize` 用 `auto`，`backgroundRepeat` 用 `repeat`，`backgroundAttachment` 用 `scroll`，`backgroundOrigin` 用 `padding-box`，`backgroundClip` 用 `border-box`。不要保留会互相覆盖的旧简写。检查导出后的计算样式与截图，而不是只检查模型里有字符串。

### 深色模式配色保留

需要保持既有配色时，已验证的原生组标记是 `col1.constraint._c = "compatible-with-dark-mode"`；其他需要标记的组使用相同方式。当前秀米普通复制导出会将该类所在元素及其后代转换成 `data-no-dark="true"`。

仅添加 `compatibleWithDarkMode: true` 没有产生同样的导出结果；也不能假设写进原始 HTML 的 `data-no-dark` 会自动在秀米保存后保留。必须从保存后重新载入的草稿执行实际复制，检查有背景或文字颜色的可见节点仍受保护。这是当前编辑器的实测行为，不能替代微信端预览验证。

### 嵌套 HTML 与叠层

不要把原稿的复杂 `<section>/<div>` 结构直接交给将其转为 `<p>` 的文本块构建路径；浏览器自动闭合段落可能破坏布局。微信目标应尽量使用自然文档流、行/列布局与行内样式。若设计有 `absolute/fixed` 定位、零高度背景或重叠 SVG，分别检查秀米保存、普通复制和微信保存后的位置，不能从本地正常显示推断平台处理后也正常。

## 完成条件

在用户授权的目标草稿中做功能测试，随后恢复最终内容：

1. 点击整个外框的边缘，菜单应出现布局/边框/阴影相关操作；点击“复制”再按 Ctrl+V，确认复制了外框与正文，而不是只复制文字。
2. 输入足以超过原框高度的正文，确认外框撑高，后续内容按顺序下移。检查原稿中的固定网格行高或固定外层高度是否造成溢出。
3. 选中原生图片，从“我的图库”实际换图，确认仍保持照片列数、比例、说明位置和边框。
4. 恢复最终稿，实际点击可见的“保存”，等待对应草稿的成功保存响应或明确成功提示，再重新载入。URL 已有稿件编号本身不能证明这次保存完成；不要在尚未完成保存时刷新。
5. 从重新载入的稿件点击“导出”→“继续用复制粘贴”，实际按 Ctrl+C，读取剪贴板 HTML。它才是普通复制功能的实际输出，不是编辑器 DOM 截图或模型序列化的替代品。
6. 在目标手机宽度与至少一个宽屏宽度对比原稿和复制 HTML。检查横向溢出、字体/行距、装饰、照片列数、背景角度/层级/透明度、图片加载、动画位移和页尾署名。为截图暂停动画后恢复播放。

公众号可写且已获授权时，再按用户约束执行粘贴、保存、重开或预览验证；仅有秀米结果时，明确没有实测微信保存往返，不保证所有客户端像素完全相同。技能推荐模块化不构成公众号操作授权。

交付草稿链接及简短图形化编辑说明，解释如何复制整个框、换图、插入图片、保存和完整复制。用户要求备份时保留原生组件备份；普通复制 HTML 再作为单个文本块导入，会失去原生模块层级。清理本次临时脚本、测试 HTML、截图及错误上传的临时素材时，只处理可以确认由本次任务创建且未被成品引用的项。
